## 2. 上传受理（到 queued / pending）

入口：`POST /api/upload`（multipart `file`；可选表单 `watermark`；可选 Header `X-Request-ID`）。

```mermaid
flowchart TD
  Start([收到上传请求]) --> Auth{鉴权通过且未冻结?}
  Auth -->|否| E401[401 / 403]
  Auth -->|是| Form{FormFile file OK?}
  Form -->|否| E400[400 40001 invalid input]
  Form -->|是| Base[filepath.Base 文件名]
  Base --> Ext{扩展名在 allowed_exts?}
  Ext -->|否| E400
  Ext -->|是| Eng{Converter 引擎可映射?}
  Eng -->|否| EMap[错误：扩展名未映射引擎]
  Eng -->|是| Size1{声明大小 ≤ max_size?}
  Size1 -->|否| E400
  Size1 -->|是| WM{副水印 rune ≤ 255 且 Request-ID ≤ 128?}
  WM -->|否| E400
  WM -->|是| Tmp[CreateTemp + LimitReader 拷贝]
  Tmp --> Size2{实际大小 ≤ max_size?}
  Size2 -->|否| E400
  Size2 -->|是| Mag{validate_magic?}
  Mag -->|开启且失败| E402[400 40002 ERR_FILE_MAGIC]
  Mag -->|通过或关闭| Struct{OOXML ZIP 成员 / OLE 流校验}
  Struct -->|失败| E403[400 40003 ERR_FILE_STRUCTURE]
  Struct -->|通过| Save[SaveUpload → upload/uid/fileid_filename]
  Save --> DB[写 upload：status=pending]
  DB -->|写库失败| Rollback[删已落盘文件 + 500]
  DB -->|成功| Enq{Queue.TryEnqueue}
  Enq -->|入队成功| Queued[CAS pending→queued]
  Enq -->|队列满 / 未配置| KeepPend[保持 pending<br/>等 requeue]
  Queued --> OK[200：fileid / request_id / status]
  KeepPend --> OK
```

要点：

- 校验失败：**不入正式盘、不入库、不入队**（临时文件在 defer 中删除）。
- 写库成功后入队失败：记录留在 `pending`，由 `requeue_interval` 周期 `ListForRequeue` 补入。
- 入队后仅当仍为 `pending` 时才更新为 `queued`，避免覆盖 Worker 已推进的状态。

## 3. 转换与重试

```mermaid
flowchart TD
  Job[Worker 领取 Task] --> Conv[UpdateStatus → converting]
  Conv --> Load[加载 upload / 解析 uid]
  Load -->|用户缺失| Fail[failConvert]
  Load -->|OK| PdfRow[创建或更新 pdf：generating<br/>路径 output/uid/fileid_….pdf]
  PdfRow --> Ensure[EnsureUserOutputDir + 清旧目标]
  Ensure --> Cvt[Converter.Convert 受 office_timeout 约束]
  Cvt -->|超时/失败| Fail
  Cvt -->|成功| WM{需水印?}
  WM -->|否| Stat[Stat PDF]
  WM -->|是| Apply[Watermarker.Apply]
  Apply -->|超时| FailRm[删 PDF + failConvert]
  Apply -->|其它失败| Warn[保留无水印 PDF<br/>warn_code=WARN_WATERMARK]
  Apply -->|成功| Stat
  Warn --> Stat
  Stat -->|缺失| Fail
  Stat -->|OK| Done[pdf=completed + pdflog generate]
  Done --> ArchOK[ArchiveUpload completed → expired]

  Fail --> Rec[RecordFailure：status=failed<br/>retry_count++]
  Rec --> Lim{retry_count ≤ converter.retry_count?}
  Lim -->|是| Wait[保持 failed<br/>retry_interval 后再入队 → queued]
  Lim -->|否| ArchFail[ArchiveUpload failed<br/>error_code=ERR_RETRY_LIMIT_EXCEEDED → expired]
```

辅助循环：

| 循环 | 选取 | 行为 |
|------|------|------|
| requeue | `pending\|queued\|converting` | `TryEnqueue`；仅 `pending`→`queued` |
| retry | `failed` 且 `retry_count ≤ retry_count` 且已过间隔 | `TryEnqueue`；`failed`→`queued` |

`retry_count` 配置为**额外**次数：配置为 2 时最多尝试 3 次；第 3 次失败后 `retry_count` 变为 3，触发超限归档。

## 4. 归档与用户删除

```mermaid
flowchart TD
  Trig{触发}
  Trig -->|转换成功| A1[final=completed, dest=expired]
  Trig -->|重试超限| A2[final=failed, dest=expired]
  Trig -->|DELETE 上传| A3[final=deleted, dest=trash]

  A1 --> Arch[ArchiveUpload]
  A2 --> Arch
  A3 --> Arch

  Arch --> Move{MoveToExpired / MoveToTrash}
  Move -->|源不存在| Warn[WARN，moved_path 空，继续]
  Move -->|其它失败| Abort[中止，保留 upload 行]
  Move -->|成功| Tx[事务：插入 upload_history<br/>Unscoped 硬删 upload]
  Warn --> Tx
  Tx --> End([upload 表不再保留该行<br/>GET 可走 history 快照])
```

说明：

- `upload` 表仅保留待转/进行中记录；终态立刻归档。
- 归档目录按 `expired|trash` + 按日路径；`archive_dir` / `moved_path` 写入 `upload_history`。

## 5. 定时清理（归档之后）

```mermaid
flowchart LR
  Tick[cleanup.interval] --> H[expireHistory]

  H --> H1{history_ttl 开启?}
```

## 6. 状态机

### 6.1 upload（活表）→ upload_history.final_status

```mermaid
stateDiagram-v2
  [*] --> pending: Create
  pending --> queued: TryEnqueue / requeue
  queued --> converting: Worker
  converting --> converting: 仍在执行
  converting --> failed: RecordFailure
  failed --> queued: retry 再入队
  pending --> [*]: 用户删除 → history deleted (trash)
  queued --> [*]: 用户删除 → history deleted (trash)
  converting --> [*]: 成功 Archive → history completed (expired)
  failed --> [*]: 超限 Archive → history failed (expired)

  note right of pending
    队列满时停留 pending
  end note
```

活表上的 `completed` / `deleted` 等终态字符串主要用于 history 的 `final_status`；成功路径在 Worker 内直接归档，不长期停留在 `upload.completed`。

### 6.2 pdf

```mermaid
stateDiagram-v2
  [*] --> generating: Create/Update
  generating --> completed: 导出成功（水印失败可带 WARN_WATERMARK）
  generating --> failed: 转换/超时/写库失败
  completed --> expired: PDF TTL 清理
  completed --> deleted: 用户删 PDF（若启用）
```

## 7. 与代码入口对照

| 阶段 | 主要代码 |
|------|----------|
| HTTP | `internal/handlers/upload.go` → `UploadService.Upload` |
| 校验 | `internal/validate` + `config.UploadConfig` |
| 落盘 | `internal/storage.SaveUpload` |
| 入队 / Worker | `internal/queue`（`TryEnqueue` / `process` / requeue / retry） |
| 转换 | `internal/converter` |
| 归档 | `CleanupService.ArchiveUpload` |
| 删除上传 | `UploadService.Delete` → trash |
| 查询终态 | `GetDetail`：先 `upload`，再 `upload_history`；客户端亦可用 `GET /api/pdf/events`（SSE）替代轮询 `status` |
